# Sharing stages and inviting clients

[Guide home](README.md) · [Accounts and ownership](ACCOUNTS.md) · [Review and recovery](EXPORTS_AND_RECOVERY.md)

## Choose the right link

| Share | Result |
| --- | --- |
| Stage access: Can use | An existing account creates its own layouts referencing the source stage. |
| Stage access: Can edit | That account can also collaborate on the source stage. |
| Organisation sharing | Team members receive access through membership. |
| Client stage invitation | Each registration creates a separate organiser-owned layout. |
| Layout edit link | Every holder edits the same existing layout. |
| Organisation invitation | A signed-in account joins the private team. |

Only the source creator manages its stage sharing. Do not use a collaborative layout edit link when every performer needs a separate arrangement.

## Individual stage access

Open **Share stage**, enter the existing account's email and choose Can use or Can edit. Can use is sufficient for equipment layouts. Can edit permits source-stage changes.

The recipient creates layouts from Stages. Directly created layouts belong to that recipient, with an optional Share this layout with the stage owner choice. Stage ownership alone does not reveal a recipient's private layout.

## One invitation for a festival or many clients

1. Save the stage and its installed/available equipment.
2. Open **Share stage**.
3. Choose the destination for new client layouts: personal dashboard or an organisation you administer.
4. Create the client invitation.
5. Send that same link to everyone.

For an organisation destination, share the stage with that team first. Organisation stock and branding follow the invitation.

Each client enters a name and chooses **Start my layout**. They receive a private edit link and a separate layout referencing the stage version. No manual performance entry or client account is required.

## What clients can do

Clients place equipment, adjust labels, rotation and components, add notes, save, submit for review and export. Stage geometry and installed equipment are locked.

The invitation page can resume the previous registration in that browser or create another layout. Keep **Copy my edit link** as the reliable way back to the same arrangement.

Signed-in clients retain account access to their layouts. An anonymous client can sign in and choose **Save to my dashboard**. The organiser remains the owner of invitation-created layouts.

## Collaborative layout links

Use **Details & sharing** to manage a layout's edit link. Anyone holding it can edit that layout, so share it with the people who should collaborate on the same arrangement.

The authorised organiser can replace or revoke an edit link independently of the stage invitation. Deleting an owned layout also stops its edit link.

Replacing or disabling the stage invitation stops new registrations. Existing individual layout links keep working.

## Remove shared entries from your library

Choose **Remove from my library** on a shared stage/layout card, then confirm. It is a personal list preference: the original document, other people's access and your independent layouts remain intact.

Open **Removed items** in Stages or Layouts, choose **Restore to my library**, then **Back to library**. Shared removals persist across reloads.

To end another person's actual access, change the stage grant, organisation membership, optional stage-owner sharing or private edit link that provided it.

## Source-stage updates

Layouts reference a saved stage version. Editing the source does not silently change old layouts.

Curtains are part of that pinned source version. Clients see the saved curtain styling and collide with its centre line when its collision checkbox is enabled, but cannot move its endpoints or edit its appearance. Save a new source version and explicitly apply it to existing layouts when changing curtains.

When a newer source exists, the layout dashboard card shows **Update to stage version N** for users with access to that source. Confirm to apply it. The same action remains available in **Details & sharing**. Equipment positions stay in place; inspect them for overlaps and fit. This is separate from restoring a layout's own equipment revision.

## Hide or remove public library entries

App **Admins** and the **Owner** can choose **Hide from public library** on equipment or stage cards. Hidden entries disappear from normal browsing and default canvas palettes without being deleted or returned to reviews. Choose **Hidden items**, then **Show in public library** to restore one. Visibility survives restarts and published artwork updates; changing it does not create a new stage version.

Hiding is a catalogue preference, not an access revocation. Existing layouts and deliberately shared available-equipment snapshots keep working. A known stage link can still be used. To stop new layouts on a public stage, choose **Remove public stage** and confirm. Saved source versions remain available to existing layouts, and the creator's private original remains intact. A later approval can publish that source again. Generic stages are maintained separately by the app Owner.
